# Skill Factory - Skill 生产工厂

这是一个用于创建和优化 skills 的元技能。它帮助你系统化地设计、编写、测试和改进 skills。

## 核心流程

创建一个 skill 的完整流程：

1. **需求分析** - 理解 skill 要解决什么问题
2. **设计规划** - 确定 skill 的结构和内容
3. **编写实现** - 按照规范编写 SKILL.md
4. **测试验证** - 用真实场景测试 skill
5. **迭代优化** - 根据反馈改进 skill

## 第一步：需求分析

在开始编写之前，先理解用户的需求：

### 关键问题

1. **这个 skill 要做什么？**
   - 具体的功能和目标
   - 解决什么问题
   - 预期的输出

2. **什么时候应该触发这个 skill？**
   - 用户会说什么样的话
   - 什么样的上下文
   - 关键触发词

3. **skill 的类型是什么？**
   - 工作流类型（多步骤指导）
   - 工具类型（快速参考和代码示例）
   - 设计类型（创意指导和原则）
   - 分析类型（数据处理和洞察）
   - 元技能类型（管理其他 skills）

4. **需要什么资源？**
   - 是否需要脚本（scripts/）
   - 是否需要参考文档（references/）
   - 是否需要资源文件（assets/）

### 需求收集策略

如果用户的需求不够清晰，主动询问：
- "这个 skill 的主要使用场景是什么？"
- "你希望用户说什么样的话来触发它？"
- "预期的输出是什么样的？"
- "有没有类似的 skill 可以参考？"

## 第二步：设计规划

基于需求分析，设计 skill 的结构。

### Skill 文件结构

```
skill-name/
├── SKILL.md (必需)
│   ├── YAML frontmatter
│   └── Markdown 指令
└── 可选资源
    ├── scripts/      - 可执行脚本
    ├── references/   - 参考文档
    └── assets/       - 资源文件
```

### YAML Frontmatter 设计

```yaml
---
name: skill-name
description: 清晰描述何时触发和做什么。包含具体场景和关键词。
---
```

**Description 编写原则**：

1. **明确触发条件**
   - 使用"Use this skill when..."或"当用户..."
   - 列出具体的触发场景
   - 包含关键词和短语

2. **要"pushy"一点**
   - Claude 倾向于 undertrigger（不够主动使用 skill）
   - 在 description 中多列举触发场景
   - 例如："Make sure to use this skill whenever..."

3. **具体而非抽象**
   - ❌ "帮助用户写内容"
   - ✅ "当用户想要生成短视频脚本、优化开头钩子、或创作小红书封面配文时使用"

### 内容结构设计

根据 skill 类型选择合适的结构：

**工作流类型**：
```markdown
# Skill 名称

## 概述
简要说明这个 skill 做什么

## 工作流程
### 第一步：[步骤名]
具体指令

### 第二步：[步骤名]
具体指令

### 退出条件
何时完成

## 最佳实践
使用建议
```

**工具类型**：
```markdown
# Skill 名称

## 快速开始
最简单的使用方式

## 常见任务
### 任务1
代码示例

### 任务2
代码示例

## 最佳实践
使用建议

## 参考
详细文档链接
```

**设计类型**：
```markdown
# Skill 名称

## 设计原则
核心理念

## 创作指导
### 原则1
说明和示例

### 原则2
说明和示例

## 避免事项
反面案例

## 示例
优秀案例
```

## 第三步：编写实现

按照规范编写 SKILL.md。

### 写作风格指南

1. **使用祈使句**
   - ✅ "分析选题的爆款潜力"
   - ❌ "你应该分析选题的爆款潜力"

2. **解释"为什么"**
   - 不要只说"必须这样做"
   - 解释背后的原因
   - 帮助 AI 理解意图

3. **避免过度强制**
   - 少用 MUST、ALWAYS、NEVER（全大写）
   - 用"建议"、"通常"、"最好"等词
   - 给 AI 一定的灵活性

4. **提供示例**
   - 用具体例子说明
   - 包含输入和输出
   - 展示最佳实践

5. **保持简洁**
   - SKILL.md 主体 <500 行
   - 复杂内容放到 references/
   - 使用清晰的章节结构

### 内容组织原则（Progressive Disclosure）

三层加载系统：

1. **Metadata**（name + description）
   - 始终在上下文中
   - ~100 词

2. **SKILL.md 主体**
   - skill 触发时加载
   - <500 行（理想）

3. **Bundled resources**
   - 按需加载
   - 无限制

### 示例模板

```markdown
---
name: example-skill
description: 当用户想要[具体场景1]、[具体场景2]、或[具体场景3]时使用。支持[功能1]、[功能2]和[功能3]。触发词包括：[关键词1]、[关键词2]、[关键词3]。
---

# Skill 标题

简要说明这个 skill 的目的和价值。

## 何时使用

明确的使用场景：
- 场景1：具体描述
- 场景2：具体描述
- 场景3：具体描述

## 工作流程

### 步骤1：[名称]

清晰的指令，解释为什么这样做。

**示例**：
输入：[示例输入]
输出：[示例输出]

### 步骤2：[名称]

继续指导...

## 最佳实践

- 建议1：说明和原因
- 建议2：说明和原因
- 建议3：说明和原因

## 常见问题

### 问题1
解决方案

### 问题2
解决方案
```

## 第四步：测试验证

编写完成后，用真实场景测试 skill。

### 测试方法

1. **准备测试用例** - 2-3 个真实的用户请求，覆盖主要使用场景，包含边缘情况
2. **测试触发** - 检查是否正确触发，是否误触发
3. **测试输出** - 输出是否符合预期，质量是否达标，是否有遗漏
4. **收集反馈** - 哪里做得好，哪里需要改进

### 测试清单

- [ ] Description 是否清晰描述了触发条件
- [ ] 在正确的场景下触发
- [ ] 不在错误的场景下触发
- [ ] 输出质量符合预期
- [ ] 指令清晰易懂
- [ ] 没有歧义或矛盾
- [ ] 示例准确有效
- [ ] 文档完整

## 第五步：迭代优化

根据测试反馈改进 skill。

### 优化方向

1. **优化 Description** - 如果触发不准确，调整 description，添加更多触发场景和关键词
2. **优化指令** - 如果输出不符合预期，增加更多细节和示例
3. **优化结构** - 如果内容混乱，重新组织章节
4. **优化资源** - 按需添加 scripts/、references/、assets/

## Skill 类型参考

### 工作流类型
多步骤指导，明确的阶段划分，用户交互点，迭代循环。示例：li-topic、li-workflow

### 工具类型
快速参考，代码示例，最佳实践，常见任务。示例：claude-api、li-cover

### 设计类型
设计原则，创意指导，风格指南，避免事项。示例：li-writer

### 分析类型
数据处理，模式识别，洞察提取，报告生成。示例：li-analyzer

## 高级技巧

### 模块化设计
如果 skill 支持多个功能，拆分为独立模块，支持单独调用或组合使用。示例：li-topic 的三模块设计。

### 脚本集成
重复性任务放到 scripts/ 目录，在 SKILL.md 中引用。

### 参考文档
内容超过 500 行时，将详细内容移到 references/，主文件保持简洁。

## 常见问题

**Description 应该多长？** 1-3 句话，~100 词。包含触发条件、功能、关键场景和关键词。

**SKILL.md 应该多长？** 理想 <500 行。超过则将详细内容移到 references/。

**如何避免 undertrigger？** 在 description 中列出更多触发场景，包含更多关键词，使用"Make sure to use this skill whenever..."。

**如何避免 overtrigger？** 在 description 中明确"DO NOT trigger when..."，列出不应触发的场景。

**应该用中文还是英文？** 根据目标用户决定，可以混用（description 英文，内容中文）。

## 最佳实践总结

1. **从需求出发** - 先理解问题，再设计方案
2. **保持简洁** - 只写必要的内容
3. **提供示例** - 用具体例子说明
4. **解释原因** - 不只说"怎么做"，还说"为什么"
5. **持续迭代** - 根据反馈不断改进
6. **模块化设计** - 支持灵活组合
7. **测试验证** - 用真实场景测试

记住：好的 skill 是迭代出来的，不是一次写成的。
